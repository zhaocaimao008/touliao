```bash

```

**预期过程**:
- 自动执行所有 8 个部署阶段
- 自动进行验证和监控
- 自动处理失败和回滚
- 总耗时: ~2.5 小时

### 方式 2: 分步手动部署

```bash
# Step 0: 部署前检查
./scripts/deployment/00-pre-deployment-check.sh

```

## 📊 实时监控

部署过程中，开启独立的监控终端：

```bash
# 启动实时监控系统
./scripts/deployment/realtime-monitor.sh
```

**监控内容**:
- 灰度环境: Pod 数、延迟、错误率、资源使用
- 全量环境: 各区域健康状态、可用性
- 数据库: 连接数、查询性能
- Redis: 缓存命中率、操作延迟
- 系统: CPU、内存、磁盘、网络
- 告警: 活跃告警和问题追踪

**关键告警阈值**:
- 延迟 P95: > 500ms → 立即回滚
- 错误率: > 1% → 立即回滚
- 可用性: < 99% → 立即回滚
- CPU: > 85% → 警告
- 内存: > 90% → 警告

## 🔄 故障处理

### 场景 1: 灰度 5% 失败

```bash
# 立即回滚灰度
./scripts/deployment/rollback-procedures.sh
# 选择: 1 (灰度回滚)

# 检查日志
tail -f /tmp/deployment-logs/canary-*.log

# 修复问题
# ...

# 重新启动部署
./scripts/deployment/main-parallel-deploy.sh
```

### 场景 2: 全量 50% 失败

```bash
# 部分回滚 (保留灰度 100%)
./scripts/deployment/rollback-procedures.sh
# 选择: 2 (全量部分回滚)

# 保留灰度环境继续观察
# 手动修复全量问题
# ...

# 重新推进全量
./scripts/deployment/10-deploy-full-5percent.sh
```

### 场景 3: 严重故障需要完全回滚

```bash
# 执行紧急回滚
./scripts/deployment/rollback-procedures.sh
# 选择: 5 (完全系统恢复)

# 这将:
# - 回滚所有 Deployment
# - 清理灰度资源
# - 重启所有服务
# - 清空缓存
# - 恢复前一个稳定版本

# 完整恢复耗时: ~10 分钟
```
