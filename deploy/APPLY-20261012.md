## 2. 让 www-data 能读 uploads（X-Accel 的前置条件；后端打开 `UPLOADS_X_ACCEL=1` 之前做）

现状：`/home/ubuntu` 750 ubuntu:ubuntu；其下 gh-mirror/touliao/backend-v2/uploads 均 755。只缺 `/home/ubuntu` 的穿越（x）权限。

推荐（只给 www-data，需装 acl 包）：

```bash
sudo apt-get install -y acl
sudo setfacl -m u:www-data:x /home/ubuntu
sudo -u www-data test -r /home/ubuntu/gh-mirror/touliao/backend-v2/uploads/files && echo OK
```

备选：`sudo chmod o+x /home/ubuntu` —— 任何本机用户都能进入 /home/ubuntu 下所有 755 的子目录（其他项目、可能含世界可读的 .env），**不推荐**。

回滚：`sudo setfacl -x u:www-data /home/ubuntu`（或 `sudo chmod o-x /home/ubuntu`）。之后后端必须关掉 `UPLOADS_X_ACCEL`，否则 /uploads 全部 403/404。
新上传文件的权限取决于后端进程 umask（目前 022 → 文件 644，可读）；若以后改 umask 要复查。

## 6.（可选，后续，**不建议现在做**）TURNS 走 443：nginx stream + ssl_preread

目的：只放行 443 的网络里，客户端用 `turns:turn.touliao.cc:443?transport=tcp` 连 coturn。

前置：`sudo apt-get install libnginx-mod-stream`（当前 modules-enabled 为空，stream 模块未装）；DNS `turn.touliao.cc` → 13.213.234.231；coturn 证书需覆盖该名字。

nginx.conf 顶层（http 块之外）：

```nginx
load_module modules/ngx_stream_module.so;   # 若装包后 modules-enabled 已自动加载则省略

stream {
    map $ssl_preread_server_name $tl_443_upstream {
        turn.touliao.cc  127.0.0.1:9443;      # → 下面的 TURN 中转
        default          127.0.0.1:8443;      # → 所有 HTTPS 站点
    }
    server {
        listen 443;
        listen [::]:443;
        ssl_preread on;
        proxy_pass $tl_443_upstream;
        proxy_protocol on;                     # 不支持变量，统一带上，TURN 那一路在下面剥掉
        proxy_connect_timeout 5s;
        proxy_timeout 1h;
    }
    # coturn 不认 PROXY 头：本地接收并剥掉，再纯 TCP 转给 coturn TLS 端口
    server {
        listen 127.0.0.1:9443 proxy_protocol;
        proxy_pass 172.26.12.15:5349;
        proxy_timeout 1h;
    }
}
```

http 侧：**同机全部 ~30 个站点**的 `listen 443 ssl http2;` / `listen [::]:443 ...` 都要改成
`listen 127.0.0.1:8443 ssl http2 proxy_protocol;`，并加 `set_real_ip_from 127.0.0.1; real_ip_header proxy_protocol;`，否则所有站点日志/限流拿到的客户端 IP 都变成 127.0.0.1。

风险（为什么不建议）：
1. 改动面是整台机器所有 HTTPS 站点，不只是投聊；任何一个漏改 → nginx 起不来，全站停。
2. certbot `--nginx` 续期/新签会往站点里写回 `listen 443 ssl`，与 stream 的 443 冲突 → 续期后 reload 失败。需要全部改成 `certbot certonly --webroot`。
3. coturn 不支持 PROXY protocol，看到的客户端 IP 全是本机 → 按 IP 的配额/日志/封禁失效。
4. WebRTC 的 TURN/TLS 客户端不一定发 ALPN，只能靠 SNI；部分 Android/旧客户端可能不发 SNI → 落到 default 走 http，失败。
5. HTTP/2 + 多一跳 stream 代理，增加延迟与 nginx 连接数（每连接 ×2，第 3 步的 worker_connections 要再放大）。
6. 回滚要同时还原 nginx.conf 和全部站点文件。

替代方案：单独一台小实例/独立公网 IP 上让 coturn 直接监听 443（`tls-listening-port=443`），零耦合。建议先用 coturn 日志/prometheus 观察 5349 连不上的真实比例再决定。
