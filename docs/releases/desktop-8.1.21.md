# Windows 8.1.21

## 发布内容

- 每次双击桌面投聊图标直接打开下一个空闲账号窗口，不弹出窗口编号选择框，不唤起已打开的窗口。
- 登录页、个人设置和托盘的新增账号窗口入口使用同样的自动分配行为。
- 在初始化配置、日志和 Chromium 会话之前，按账号目录获取 Electron 原生进程锁，支持并发启动。
- 1 号窗口保留原版数据目录，其他窗口沿用 8.1.20 的独立目录；完全退出窗口后，下次启动优先复用空闲目录及其原有数据。
- 不再限制为 5 个窗口。自动分配上限为 100 个，以避免无法获得进程锁时无限循环。
- 保留显式 `--profile=N` 参数兼容性，同编号重复启动只唤起对应窗口。

## 发布边界

本次只发布 Windows 8.1.21，继续配套线上 Backend 8.0.1 / Web 8.1.19，不重启后端、不发布手机包。
安装更新前需从托盘完全退出所有旧版投聊进程。关闭到托盘的窗口仍占用其账号目录，不视为空闲。
账号目录持久化意味着复用窗口可能恢复上次登录，这不是每次启动创建永久新账号目录。

## 验证入口

- `node --test desktop-electron/scripts/profiles.test.js`：自动分配、超过 5 个窗口、空闲目录复用、显式参数兼容、目录错误和耗尽边界。
- `desktop-electron/scripts/multi-window-smoke.cjs`：无 `--profile` 参数连续启动 6 个真实 Electron 进程，其中 2 个并发；验证目录和 localStorage 隔离、不唤起隐藏的旧窗口、退出重开持久化以及登录图片加载。使用临时账号目录访问真实配置和未登录接口，不创建服务端账号，不使用已有登录凭据。
- 冒烟脚本支持 `TOULIAO_PACKAGED_APP=1`，用实际 Windows 安装包中的 app.asar 复测。Linux 运行时使用与 Windows 构建锁文件一致的 Electron 30.5.1。
- 发布后校验最新版本、Ed25519 更新元数据签名、安装包 SHA-512 以及公开下载入口。

Linux Electron 交互测试不能替代 Windows 真机安装验收。现有发布链路提供更新元数据签名，但未配置 Windows Authenticode 发布者证书。
