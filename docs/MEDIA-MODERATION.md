图片和视频上传审核

此前媒体入口在未接入审核服务时固定返回 `MEDIA_MODERATION_UNAVAILABLE`。
现在可启用本机 NudeNet 检测：文件经过现有权限、大小、扩展名/实际字节校验后，
检测通过才创建消息、登记访问权限或发布头像/朋友圈资源。
无需第三方 API 密钥，也不向外部服务发送用户媒体。

能力与限制

- 使用 NudeNet 3.4.2 自带的 320n ONNX 模型，校验版本和权重 SHA-256。
- 拒绝置信分数不低于 0.6 的外露生殖器、女性乳房、肛门及臀部检测结果。
  分数是模型判断，不是已在投聊真实数据上测量的识别准确率；存在误判和漏判。
- 静态图片先解码、按方向旋转、缩放后检测；动画最多均匀选取 32 帧。
- 视频通过 ffprobe 确认可解析且只有一条视频轨；最多每秒一帧，
  长视频均匀降低采样率，最多检测 32 帧。没有检测每一帧。
- 这是**裸露内容筛查**，不覆盖全部违法、有害、暴力、骚扰内容。
  继续使用现有举报/客服、账号封禁和消息删除进行人工处理。
- 未配置、依赖损坏、模型不匹配、超时或响应格式异常均拒绝上传，
  不会以“审核通过”兜底。损坏媒体返回 400，内容被拒绝返回 422，
  检测不可用/繁忙返回 503。
- 无字节审核的云 PUT 凭证继续关闭；现有客户端自动回退本地上传。
  本地上传和分片上传均经过实际检测，文档和确认没有视频轨的录音不需视觉检测。

部署（已验证 Ubuntu / Python 3.12 / Node 22）

系统需已有 `/usr/bin/ffmpeg`、`/usr/bin/ffprobe` 和 Python venv。
在 backend-v2 目录运行：

```bash
bash scripts/media-moderation/install.sh /absolute/path/to/media-runtime
```

在该服务的 `.env` 中配置：

```dotenv
MEDIA_MODERATION_PROVIDER=local-nudenet
MEDIA_MODERATION_PYTHON=/absolute/path/to/media-runtime/bin/python
```

重启投聊后端后，用专用账号验证发送图片、视频及接收下载。
只检查 `/health` 不能证明媒体检测可用，部署验收必须包含真实文件上传。
如移除这两个配置，媒体上传恢复为拒绝状态；不会降级为免检测。

资源和存储

- 同时最多两个检测任务；超出立即返回繁忙，不无限堆积等待队列。
- 检测进程仅继承必要的运行环境，不继承应用凭证，CPU 推理限制为单线程。
- 图片解码上限 4000 万像素；检测帧最长边 640 像素。
- 子进程限时 60 秒；视频探测和解码另有 8 秒/40 秒限制。
  超时时终止整个进程组（含 ffmpeg），并删除私有工作目录。
- 头像、朋友圈等图片/视频先写入禁止静态访问的 `.media-pending` 目录；
  同一批文件全部通过后才移入目标目录。多图中有一项失败则清理整批。
- 聊天文件在检测通过前不登记 `file_registry`，分片在审核期间禁止续写、
  重建或重复完成。失败时清理临时文件和分片元数据。

验证

- `test/media-moderation-enabled.test.js`：通过、拒绝、故障、伪装 MIME、
  私有暂存、多图回滚、分片发布与审核期间的并发访问。
- `test/local-media-scanner.test.js`：判定格式、真实拒绝码、失败关闭、超时及清理。
- `python -m unittest discover -s scripts/media-moderation -p 'test_*.py'`：
  分类阈值与异常输出处理。内容拒绝用例使用合成模型判定，不代表已完成模型准确率评估。
- 另须以实际本机模型跑正常图片、视频和动画的 HTTP 上传、接收与下载。
