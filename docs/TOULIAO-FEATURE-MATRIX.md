## 覆盖说明（诚实边界）

- 标记 **PASS** 的项，均有明确的实测证据支撑（e2e用例通过记录、生产日志观测、curl直接验证），不是"代码存在就判定通过"。
- 标记 **PARTIAL** 的项，代码链路基本完整，但本轮时间/环境所限未做逐项UI交互式实测，建议下一轮针对性补充。
- 标记 **BLOCKED** 的项，是本机环境的硬性限制（无Android模拟器可执行文件、无macOS、容器内Electron沙箱限制），不代表功能本身有问题，也不能反过来当作"已验证正常"。
- Android/iOS 原生端因无法真机/模拟器交互测试，其功能状态主要来自**静态代码审计**（确认两端各自完整实现了对应模块），而非实际点击验证，请知悉这层证据强度的差异。
