# 媒体凭据升级实施流程

适用 `/uploads` 长期登录 JWT URL 下线。实施人员在隔离环境完成以下步骤后才排发布窗口；此文件不表示生产已经执行。当前仓库没有能让旧二进制弹出强升界面的远程开关。

1. **先准备客户端**：以包含本修复的提交构建 Android/iOS 包，确认正式签名、升级覆盖安装和图片/语音/视频/下载/跨源重定向可用。登记包的版本号、构建号、摘要、可信商店/企业分发位置及验收记录；未取得这些实际值不宣布截止日期。短期票据接口已经存在，可先发能使用 Bearer/票据的客户端，再部署后端拒绝长期 query 的版本。
2. **过渡窗口**：在既有可信商店/企业分发、下载页和管理员公告中发布修复包及明确的媒体访问截止日期。统计发行平台/版本的升级覆盖率，只保留聚合计数，禁止收集 URL query、登录 JWT 或 Authorization。旧 Windows 客户端使用 `desktop-electron/SECURITY-RELEASE.md` 的独立信任引导流程。旧客户端不能靠不支持的新配置字段实现强升级。
3. **截止门控**：后端不依赖自报版本。`/uploads?token=<登录JWT>`、空/重复 token、access_token/refresh_token 均拒绝；可识别的旧凭据返回 HTTP 401 与 `MEDIA_CLIENT_UPGRADE_REQUIRED`。修复客户端同源 Bearer 或单文件短票据继续允许。没有放行旧 JWT query 的开关。旧端可能只显示媒体加载失败，公告必须明确“未升级将无法打开媒体，安装后重试”。
4. **上线前日志门禁**：在隔离代理/CDN/对象存储/OTLP collector 上用合成凭据重放允许与拒绝请求；检查正常访问、上游断开、超时、404、302 和 Range 的日志及导出。nginx 配置仅保证 access log 不记 query；继承的 error log、其它虚拟主机、CDN/R2 仍需部署前配置脱敏收集或受控日志接收链路并实测。不得用关闭诊断代替验证；无法排除泄漏时日志验收 BLOCKED，不能声称全层完成。
5. **验收与处置**：记录 Bearer/票据 200、HEAD 200、Range 206、旧 query 401、撤销后票据 401。核对不含凭据的错误计数。客户端故障采用修复包或可信完整包恢复，不回退后端长期 query 接受。历史日志和凭据撤销另按受控发布窗口实施；本修复不操作生产数据。

必须填写后才能实施的清单：两端实际签名包与版本、可信分发位置、升级覆盖阈值与截止日期、代理/CDN/对象存储日志配置负责人及隔离验收输出。缺任一项，保留 NEED_VERIFY/BLOCKED，不把本文当作已经上线的强升机制。
